# 保田研の組織構造

## 部署

ゼミ運営（活動の三本柱のひとつ）は部署制で回っている。ゼミ長3名がこれらを束ねる。

```
保田研 ─┬─ 授業運営部
        ├─ イベント運営部
        └─ 広報部
   会計（横断）
```

| 部署 | 所管業務 |
|---|---|
| **授業運営部** | ・学期内スケジュール決め<br>・輪読コンテンツ決め、担当者依頼<br>・PJ決め、進行 |
| **イベント運営部** | ・イベントの管理・運営<br>・共通アウトフィット作成 |
| **広報部** | ・インスタ管理・運営<br>・保田研聴講希望フォームの管理・運営<br>・HPの管理・運営 |
| **会計** | 部署横断。ゼミ費の徴収・管理、イベント予算・精算 |

## ゼミ長

- 2024年春に本格的にポスト化。**毎学期交代が原則。**
- 男女1名ずつ＋α。3〜4名の時期を経て、**現在は3名体制が定着。**
- **役割分担は明示的には決まっていない。**実態としては暗黙の了解で分かれてきた。直近（2025秋〜2026春）の例：
  - 一方が**授業運営とゼミ全体の大きな意思決定**を拾う
  - もう一方が**イベント系・対外的な活動・会計・広報**のとりまとめを請け負う
- **ゼミ長は部署の実務をやる人ではなく、監視して必要なら巻き取る／他に移管する人。**特に合ゼミの幹事は放置すると詰まるので、進捗を見にいく責任がゼミ長にある。

> 役割分担が明文化されていないのは現状の仕様。引き継ぎのたびに再発明されるコストがあるので、**学期の頭に3名で分担を口頭合意し、Slackに書いて残す**ことを推奨する（`hoda-zemicho-assistant` がこれを支援する）。

## 名簿（メンバーDB）のスキーマ

ゼミの名簿はスプレッドシートで管理されている。列構成は以下。**実データはこのプラグインには含まれていない。**Google DriveまたはSlackにある最新版を参照すること。

| 列 | 内容 | 備考 |
|---|---|---|
| Name | 氏名 | 日本語名／英語名が混在。英語圏メンバーはローマ字表記 |
| Student Number | 学籍番号 | 個人情報。対外資料に出さない |
| J or E | 使用言語 | `J`＝日本語、`E`＝英語。**アナウンス・資料の言語判断に使う最重要列** |
| Leader | ゼミ長フラグ | |
| 部署 | 所属部署 | 授業運営部／イベント運営部／広報部／会計 |
| （イベント名）例：`8/3合宿` `9/28-29合宿` | 出欠 | イベントごとに列を追加していく運用 |
| email address (keio.jp) | 慶應メール | 個人情報。対外資料に出さない |
| year | 学年と在籍学期数 | 例：`4年生 2学期目 Senior 2nd semester`。**「何学期目か」を持っているのが重要**。入退室が自由な制度なので、学年だけでは在籍歴が分からない |
| faculty | 学部 | 総合政策 policy management ／ 環境情報 environment and information studies |
| sex | 性別 | 男女比ポリシー（5:5目標）の管理に使う |
| slack | Slack参加状況 | 新規メンバーの招待漏れ検知に使う |

シートの下部に **`留学`** セクションと **`休学`** セクションがあり、その学期に不在のメンバーを分けて管理している。**在籍者数を数えるときはこの2セクションを除外する。**

## 名簿を扱うときの注意

- **学籍番号とメールアドレスは個人情報。** 対外資料、SNS、他大学との共有物には絶対に含めない。合ゼミの参加者リストを先方に渡すときも、氏名・学年・学部までに絞る。
- **`J or E` 列は必ず見る。** 全体アナウンスや共有資料を作るときは、Eのメンバーが読める形になっているかを確認する。日本語だけで流すのは、在籍者の約4割を置き去りにすることになる。
- **`year` の「何学期目か」を見る。** 1学期目のメンバーは保田研の型を知らない。輪読の事前課題やスライド作法の説明を省略しない。
- **`留学`／`休学` セクションのメンバーも学期末には戻ってくる。** 引き継ぎドキュメントを残す価値はここにある。

## PJ（プロジェクト）チームの編成

### 構造

- **日本語チームと英語チームに分けて編成する。** 名簿の `J or E` 列がそのまま割り当ての基準。
- チーム名は **`チームN（提案先企業名）`** の形式。例：`チーム1(パナソニック)` `チーム6(Panasonic)`
- **1社に日本語チームと英語チームの両方が付くことがある。** 同じ企業に対して2つの視点から提案が出る形。例：パナソニック＝チーム1（日）とチーム6（英）、チェンジ＝チーム3（日）とチーム7（英）、アント＝チーム4（日）とチーム8（英）
- **1チーム4〜6名。** リーダーを1名立てる（名簿・編成表では先頭に太字で置く）。
- **英語チームは日本語表記版と英語表記版の名簿を両方持つ。** 対外資料や先方企業への提出物で使い分ける。

### 編成表のフォーマット

```
        チーム1(パナソニック)  チーム2(ヤマハ)   チーム3(チェンジ)  チーム4(アント)  チーム5(サツドラ)
日      【リーダー名】          【リーダー名】     【リーダー名】      【リーダー名】     【リーダー名】
        メンバー               メンバー           メンバー            メンバー           メンバー
        ...

        チーム6(パナソニック)  チーム7(チェンジ)  チーム8(アント)
英      【リーダー名】          【リーダー名】     【リーダー名】
        メンバー               メンバー           メンバー
        ...

        Team 6 (Panasonic)     Team 7 (Change)    Team 8 (Ant)
英      【Leader】              【Leader】         【Leader】
        Member                 Member             Member
```

### 編成のときに見るべきこと

- **在籍学期数を散らす。** 1学期目だけのチームを作らない。保田研の型を知っている人を各チームに最低1名入れる。
- **学年を散らす。** 4年生だけのチームは就活・卒プロで動けなくなる時期がある。
- **リーダーは在籍2学期目以上から立てる。**（→ `hoda-project-leader`）
- 留学・休学予定者は、その学期のチームに入れない（名簿の `留学`／`休学` セクションを確認）。
