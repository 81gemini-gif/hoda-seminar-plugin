# 週次運営

## コマの構成

| コマ | 内容 |
|---|---|
| **4限** | **保田先生がいるコマ。**輪読・ケーススタディ・研究発表・PJ中間/最終発表 |
| **5限** | **PJワーク。**チームごとの議論とタスク消化。月1回は進捗報告会と360°FB回 |

**4限は先生がいる時間なので、先生の時間を使う価値のある内容を置く。**単なる作業時間にしない。

## 週次スケジュールシート

授業運営部が管理するマスターシート。列構成は以下。**この列を全部埋めることが、その週の準備が完了したことの定義。**

| 列 | 内容 | 誰が埋めるか |
|---|---|---|
| `Date` | 実施日 | 学期頭に一括 |
| `Detail` | 第N回 / 休講 / イベント名 | 学期頭に一括 |
| `1コマ目（保田さんがいるコマ - 輪読）` | 4限の内容と時間配分 | 授業運営部 |
| `2コマ目（PJ）` | 5限の内容 | 授業運営部 |
| `マテリアル` | 輪読で使う資料のファイル名 | ファシリ担当 |
| `日ファシリ①` `日ファシリ②` | 日本語ファシリテーター2名 | 授業運営部 |
| `英ファシリ①` `英ファシリ②` | 英語ファシリテーター2名 | 授業運営部 |
| `ファシリ依頼` | 依頼済みかのステータス（済／未） | 授業運営部 |
| `聴講可否` | 可／不可／その他 | ゼミ長・広報部 |
| `履修生のto-do` | その週までに履修生がやること | 授業運営部 |
| `ゼミ長のto-do` | ゼミ長がその週にやること | ゼミ長 |
| `アナウンス` | その週に流す連絡 | ゼミ長 |
| `その他` | 備考、バッファの理由、リスク | 誰でも |

### 運用のポイント

- **ファシリは日本語2名＋英語2名の計4名体制。**同じコンテンツを日英両方で回す
- **`ファシリ依頼` を「済」にするまでが授業運営部の仕事。**シートに名前を書いただけでは依頼していない
- **`聴講可否` は毎回設定する。**企業の中間発表がある週、非公開情報を扱う週は「不可」。広報部が管理する聴講希望フォームと連動させる
- **`その他` にバッファの理由を書き残す。**「合ゼミ前で発表準備がバタつく可能性有 → 輪読コンテンツは決定せずバッファ確保」のような判断は、次学期の運営者に効く

## 輪読コンテンツの決め方

### 選定の母体

**ゼミ生が学期末に提出する継続フォーム。**次学期の履修希望を出す際の提出要件として、「輪読で扱うべきコンテンツ＋その輪読ファシリ資料」が含まれている。**次学期の輪読はここから選ぶ。**

つまり：

```
学期末：全ゼミ生が継続フォームで輪読候補＋ファシリ資料を提出
   ↓
学期前：ゼミ長＋授業運営部が候補から選定
   ↓
先生と相談して固める
   ↓
学期開始時：向こう1〜2ヶ月分のスケジュールが確定している状態にする
```

**学期が始まってから輪読を決め始めるのは遅い。**

### 選ぶ基準

- **保田研のテーマ**（コーポレートファイナンス、ESG投資、人的資本経営）に接続しているか
- **実際の経営陣・投資家の目線で議論できる**題材か
- 種類のバランス：**HBSケース／査読付き実証論文／直近の実事例**を混ぜる
  - 実例：Snapchatケース、花王 × オアシス（アクティビストのホワイトペーパー）、日本製鉄によるUSスチール買収、良品計画、実証会計ファイナンスの論文
- **その学期のPJテーマと接続する**題材があるとよい
- 提出者本人がファシリをやるのが基本（資料も本人が作っているため）

### 資料の形式

ファシリ資料は**PDF**でシートの `マテリアル` 列に紐づける。ファイル名の慣行：

```
（学期）輪読＿（担当者名）＿（題材）.pdf
例：秋学期輪読＿〇〇〇〇＿Snap.inc.pdf
```

## 輪読ファシリのやり方

### 事前（開催の1週間前まで）

- [ ] **事前課題を設計してSlackに投下する。**これが輪読の質を決める
- [ ] 資料（ケース本文、論文）を全員がアクセスできる場所に置く
- [ ] 日英ファシリ間で、論点と進行を揃える

### 事前課題の設計

**「読んでおいてください」だけでは輪読にならない。**保田研の事前課題は、以下のような具体的な作業を含む。

実際に出された事前課題の例（日本製鉄によるUSスチール買収）：

- ケースを読み、買収の背景・ステークホルダーの反応など要点を押さえる
- FY2022（買収提案時点）までのUSスチールの財務分析を行い、当時直面していた状況とボトルネックを深掘りする
- **各自、日鉄側またはCleveland Cliffs側の立場から、FY2022までのデータでUSスチールのEV算定と買収価額を設定する。**手法（マルチプル、DCF）は問わないが、妥当性を論じる
- 余裕があれば、その後の買収提案の動向の変遷までリサーチする

別の例（花王 × オアシス）：

- 花王にとって、オアシスの要求は短期志向か、長期的企業価値向上の一助か
- 花王は多角化で安定性を維持してきたが、オアシスは「選択と集中」を求める。どちらが企業価値最大化につながるか
- 成果が出ない場合でも企業はどの程度R&Dを続けるべきか。株主はどこまでリスクを許容するか
- ESG投資と利益は両立可能か

**共通する型**：
1. **事実を押さえる問い**（何が起きたか）
2. **手を動かす問い**（財務分析、バリュエーション）
3. **立場を取らせる問い**（あなたが〇〇ならどう判断するか）
4. **保田研テーマに接続する問い**（企業価値と社会的価値の両立）

### 当日

- [ ] 冒頭で**議論のゴール**を示す（今日は何を決めるのか／何を持ち帰るのか）
- [ ] 事前課題の回答を全員に出させる。**発言が偏らないよう指名する**
- [ ] 対立軸を作る（買い手／売り手、経営陣／アクティビスト、短期／長期）
- [ ] 先生の論点を引き出す時間を残す

### 事後

- [ ] 議論のログをSlackに残す。**休んだ人、留学中の人が追える形にする**

## アナウンス

ゼミ長がSlackに流す。

- **`J or E` 列を見て、英語話者が読める形になっているか確認する。**日本語だけで流すのは在籍者の約4割を置き去りにする
- 締切があるものは**日付と時刻**を書く
- 提出先（フォーム、Drive、Slackスレッド）を明記する
- 学期の頭は「向こう1〜2ヶ月分のスケジュール」を一度まとめて流し、チャンネルにピン留めする

Slackコネクタが使える場合は、`slack_send_message_draft` で下書きを作ってから送る。**いきなり本送信しない。**
