# バリュードライバー分解（ROICツリー／ROEデュポン）

**打ち手の提案は、必ずこの分解を経てから出す。** どのドライバーがボトルネックか特定せずに施策を並べるのは保田研では通らない。

## 前提データ

EDINET DBコネクタから `get_financials`（最大10年）と `get_segments` を取る。手元にExcelがあるならそれを使う。**最低5年、できれば10年分**を並べる。単年だけの分解は禁止。

## 1. ROICツリー

### 定義（保田研の標準）

```
ROIC = NOPAT ÷ 投下資本

NOPAT = 営業利益 × (1 - 実効税率)
投下資本 = 有利子負債 + 自己資本      … 調達サイド
         = 運転資本 + 固定資産         … 運用サイド（こちらで分解する）
```

**どちらの定義を使ったか必ず明記する。** 実務では両方使われ、値がずれる。保田研では運用サイド（事業に投下されている資本）で分解するのを基本とする。

### 分解

```
ROIC ─┬─ NOPATマージン ─┬─ 売上総利益率 ─┬─ 単価
      │  (NOPAT/売上)    │                └─ 原価率（変動費/固定費）
      │                  ├─ 販管費率 ─┬─ 人件費率
      │                  │            ├─ R&D費率
      │                  │            └─ 広告宣伝費率
      │                  └─ 実効税率
      │
      └─ 投下資本回転率 ─┬─ 運転資本回転率 ─┬─ 売上債権回転日数（DSO）
         (売上/投下資本)  │                  ├─ 棚卸資産回転日数（DIO）
                          │                  └─ 仕入債務回転日数（DPO）
                          └─ 固定資産回転率 ─┬─ 有形固定資産回転率
                                             └─ のれん・無形資産回転率
```

販管費の内訳は `get_detailed_expenses`（14カテゴリ）で取れる。**人件費率とR&D費率は必ず分けて出す。**人的資本経営の議論に直結するため。

### 実施手順

1. 10年分の各ノードの値を計算し、表にする。
2. **WACCと並べる。** ROIC − WACC（エコノミックスプレッド）がプラスかマイナスか、その推移がこのツリーの結論。WACCの推定は `hoda-valuation` の手順に従う。
3. どのノードが悪化・改善しているかを特定する。**変化幅が大きい順に3つだけ**取り上げる。
4. 可能ならセグメント別にROICを出す。全社ROICが平均的でも、セグメント別に見ると価値破壊事業が隠れていることが多い。これが提案のネタになる。

### 分解の落とし穴

- **のれんの扱い**：大型M&A後は投下資本にのれんが乗りROICが落ちる。のれん込み／除きの両方を出し、「買収の価値創造ができているか」を論点にする。
- **リース**：IFRS16以降の使用権資産は投下資本に含める。日本基準との比較時は要注意。
- **持分法投資・現預金**：事業に投下されていない資産は投下資本から除く。除いた場合はその旨を注記する。

## 2. ROEデュポン分解

### 3分解（基本）

```
ROE = 純利益率 × 総資産回転率 × 財務レバレッジ
    = (純利益/売上) × (売上/総資産) × (総資産/自己資本)
```

### 5分解（保田研の推奨）

```
ROE = 税負担率 × 利息負担率 × 売上高営業利益率 × 総資産回転率 × 財務レバレッジ
    = (純利益/税前利益) × (税前利益/営業利益) × (営業利益/売上) × (売上/総資産) × (総資産/自己資本)
```

**5分解を推奨する理由**：3分解だと「純利益率の改善」が営業改善なのか金融収支なのか税効果なのか分からない。保田研では営業の実力と財務的な化粧を切り分けることを重視する。

### 読み方

- ROEが高い理由がレバレッジだけの企業は、**ROICで見ると平凡**なことが多い。必ずROICと並べる。
- 東証のPBR1倍割れ要請の文脈では、`ROE > 株主資本コスト` が焦点。株主資本コスト（CAPM）は `hoda-valuation` で推定する。
- 各要素を競合と並べる（→ `hoda-peer-benchmark`）。単独では良し悪しが判断できない。

## 3. アウトプット

`references/tree-visualization.md` にツリー図と表の作り方をまとめてある。

- ツリー図はスライドに載せる。各ノードには**直近値と5年前の値、変化幅**を書く。悪化ノードは色を変える（保田研テンプレのアクセント色を使う）。
- 各ドライバーの10年推移は折れ線で示す。
- 最後に必ず「**どのドライバーを何ポイント動かせば、ROICがWACCを上回るか**」の逆算を1枚入れる。これが提案の骨格になる。

## 4. 提案への接続

分解結果を打ち手に落とすときの型。

| ボトルネック | 典型的な打ち手の方向 |
|---|---|
| NOPATマージン低下（原価） | 調達改革、プロダクトミックス転換、値上げ余地の検証 |
| 販管費率上昇（人件費） | 一人当たり付加価値の議論へ。単純な人員削減は保田研の社会的価値観点と衝突するので、生産性側から組み立てる |
| 運転資本回転悪化 | DSO/DIO/DPOのどれか特定。取引条件か在庫政策か |
| 固定資産回転低下 | 稼働率、遊休資産、不採算拠点。`get_facilities` `get_real_estate` で裏を取る |
| のれん込みROIC低迷 | M&A後のPMI、事業ポートフォリオ組み替え |
| レバレッジ依存の高ROE | 資本構成の最適化。ただし社会的価値・従業員・取引先への影響を必ず併記する |

**保田研では、財務的に正しいだけの打ち手は評価されない。** 企業価値向上と社会的価値向上の両立という研究会テーマに接続すること。
