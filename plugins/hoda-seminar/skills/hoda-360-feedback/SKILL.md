# 360°FB

## これは何か

**各PJの中間発表または最終発表が終わった翌週に、チーム内で全員が全員に対して書く相互フィードバック。**保田研の文化の中核で、他ゼミにない仕組み。

- **全員 → 全員**。メンバーからリーダーにも書く。リーダーからメンバーにも書く。上下関係は関係ない
- **Goodコメント**と**Moreコメント**の2本立て
- 記入はスプレッドシート。列は `記入者 / チームリーダー / 誰に対してのFBか / Goodコメント / Moreコメント`
- **言語はチームの言語に合わせる。**日本語チームは日本語、英語チームは英語。混在も可（日本語チームでも英語話者が入っていれば英語で書く）

## 何のためにやるか

- 発表という区切りで、**チームの動き方をリセットする**
- 在籍1学期目のメンバーが、自分の貢献が見えていることを知る
- リーダーが、自分のマネジメントの効き目を知る
- **人が入れ替わる前提のゼミなので、良い動き方を言語化して残す**

## Goodコメントの書き方

### 分量

**250字前後が標準。**短すぎると「特にないです」に見えて機能しない。長い人は500字以上書く。

### 型

1. **ねぎらいから入る**（「中間発表お疲れさま！」「発表お疲れ様〜！」）
2. **具体的な行動を1つ以上、名指しで挙げる**
   - ×「いつも頑張ってくれてありがとう」
   - ○「マテリアリティを筆頭に抽象的なテーマが多いプロジェクトで先のビジョンが立ちづらい時でも、本当に心からプロジェクトを楽しんでいる気持ちが伝わってきて、そのお陰でメンバーがよりポジティブな気持ちでいることができた」
3. **その行動がチームにどう効いたかを書く**
4. **その人の置かれた状況を踏まえる**（就活中、体育会、1学期目、留学前、時差、体調）
5. **前向きに締める**（「最終まで一緒に走り切ろう」）

### 保田研らしさ

- **絵文字・感嘆符・くだけた口調はむしろ推奨。**堅い評価コメントにしない
- **相手の状況を知っている前提で書く。**「4年生で残り少ない学生生活を謳歌したいだろうに」「部活が試合シーズンで忙しい中で」
- **能力ではなく行動を褒める。**「頭がいい」ではなく「電車内でも作業していたと聞いて、時間は作るものという意識を教えてもらった」

## Moreコメントの書き方

**ここが一番難しく、一番価値がある。**

### 大原則

- **「特にないです」で終わらせない。** それは相手の成長機会を奪っている。1つは必ず絞り出す
- **人格ではなく行動に向ける。**「〇〇さんは消極的」ではなく「ミーティングで意見を出す回数をもう少し増やしてほしい」
- **「今後の進め方」に接続する。**過去の指摘で終わらせず、最終発表までに何を変えるかを書く
- **自分も含める。**「私もそうなんですけど」「私も言えた立場ではないですが」という前置きが保田研では自然に使われている。指摘を上から落とさない
- **相手の制約を認めた上で書く。**「就活で忙しいのは分かった上で」「部活の試合シーズンと重なっていたので仕方ない部分もあるけど」

### 頻出パターン（実際によく書かれているもの）

| 型 | 例 |
|---|---|
| **もっと発散してほしい** | 「遠慮とかせず、自分なりの考えとか仮説をジャンジャン提示してくれると、見落としている視点を拾えるかも」 |
| **考えすぎずに一回出してほしい** | 「考えすぎず、もったいぶらず、一回アウトプットしてみてから批判的になろう。最初から正解を出す必要はない」 |
| **情報を一箇所にまとめてほしい** | 「Slackで送るだけでなくGoogle DocsかSheetに集約してほしい。今の状態だと全体像が見えない」 |
| **DMではなくチャンネルを使ってほしい** | 「誰がどれくらい稼働できてるか、誰が今何をやってるかが分かりにくい」 |
| **稼働できない期間を事前に言ってほしい** | 「○月○日〜○日はキャパると思う、と先に言ってくれれば残りで役割分担を決められる」 |
| **アウトプットのフォーマットにこだわってほしい** | 「大事な情報がどこにあるのか、どの問いに対する回答なのかが不透明。サマリ的にまとめる工夫を」 |
| **AIの文章ではなく自分の言葉で** | 「調査にAIを使うのは全然OK。ただ成果として欲しいのは、そこから何が提案できるか、自分はどう思うか」 |
| **決めきってほしい**（リーダー向け） | 「仮でもよいので自分のスタンスをいち早く決めること。完成像が見えないとみんな好きに動き始める」 |
| **頼ってほしい**（リーダー向け） | 「どれをやりたい？ではなく、あなたは〇〇だからこのタスクをお願い！と言ってほしい」 |
| **一人で抱え込まないでほしい**（リーダー向け） | 「直前に一人でラストスパートをかける形になっていた。スケジュール管理をチームで見直したい」 |
| **先輩後輩を気にせず発言してほしい** | 「一番年下で発言しにくいと思うけど、毎回の発言が鋭いので遠慮せずどんどん言ってほしい」 |

## リーダーへのFBは特に丁寧に書く

リーダーは自分のマネジメントの効き目を知る機会がここしかない。**「良いリーダーでした」で終わらせない。**

リーダーに書くときのチェック項目：

- 指示の出し方（何をやってほしいかが明確だったか）
- 決断のスピード（方向性を示せていたか）
- 情報共有の経路（DMに閉じていなかったか）
- 稼働の偏り（一人で抱え込んでいなかったか）
- 心理的安全性（発言しやすい場を作れていたか）

## Claudeがこの作業を手伝うときの原則

**下書きの代筆はしてよい。ただし以下を守る。**

1. **ユーザーが挙げた具体的な事実だけを使う。** チームメンバーの行動を勝手に創作しない。事実が足りなければ「その人が実際にやったことを2〜3個教えてください」と聞き返す
2. **Moreコメントを丸めない。** 「特に改善点はありません」に着地させない。ユーザーが言いにくそうにしていたら、言い方を柔らかくする手伝いをする（人格→行動、断定→提案、自分も含める）
3. **保田研のトーンに寄せる。** 人事評価のような硬い文体にしない
4. **相手の状況（学年、在籍学期数、就活・部活・留学）を必ず織り込む。**名簿の `year` 列が使える
5. **完成品ではなく叩き台として渡す。** 最後は本人の言葉に直してもらう。「AIの文章だと頭に残らない」というのは、このゼミで実際に指摘されていること

## 進め方のテンプレ

Claudeに手伝わせるときの入力形式：

```
チーム：チーム4（アント）／日本語
私の役割：リーダー
FBを書く相手：
- Aさん（4年2学期目、就活中）— やったこと：GTAの分析を短期間で完遂、発表前の追い込み、ムードメイク
- Bさん（2年1学期目、体育会）— やったこと：担当パートのリサーチは毎回準備してきた。質問を積極的にする。ただし発言までに時間がかかる
発表：中間発表が終わったところ
```

これがあれば、Good/Moreそれぞれ250字前後の下書きを人数分作れる。
