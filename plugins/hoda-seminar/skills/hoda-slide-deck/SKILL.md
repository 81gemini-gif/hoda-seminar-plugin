# 保田研スライド作成

## 手順

### 1. 骨子を先に決める（スライドを作り始めない）

**いきなりPowerPointを開かない。** 保田研で差が出るのは骨子の段階。

1. **キメヘンを埋める。** → `hoda-kimehen` スキルを使う。聞き手・メインメッセージ・起こしたい変化が埋まっていない状態でスライドを作り始めない。
2. **ストーリーラインを1行×N枚で書き出す。** 各スライドのワンメッセージだけを並べたリストを作り、上から読んで論理が通るか確認する。ここでユーザーに一度見せて合意を取る。
3. 各メッセージを裏付けるファクト（数字・図表）を割り当てる。**裏付けのないメッセージは削るか、裏付けを取りに行く。**

### 2. デッキの構成を決める

保田研の提案デッキには決まった並びがある。**`references/deck-structure.md` を必ず読む。**

表紙 → つかみ → 前回のリキャップ → 本プレゼンの目的 → **Executive Summary** → 目次 → 中表紙＋本編（章ごと） → Appendix

特に **Executive Summary** は保田研のデッキで最も重要な1枚。リード文＋章ごとの ✓ で、ここだけ読めば提案の全体が分かる状態にする。**スライドを作る前と作り終わった後の2回書く。**書き方と判断基準は `references/deck-structure.md` の該当節にある。

本編スライドのタイトルは **`テーマ：結論`** 形式（例：「株価成長：一時の成長曲線は直近では鈍化、再成長が課題」）。タイトルで結論、リード文で裏付け、コンテンツで図表という3層構造。

### 3. レイアウトを選ぶ

テンプレは `${CLAUDE_PLUGIN_ROOT}/assets/hoda-template.pptx`。16:9（13.333in × 7.5in）、20レイアウト。詳細は `references/template-spec.md`。

| 用途 | レイアウト名 |
|---|---|
| 表紙 | `表紙` |
| 章扉 | `中表紙` |
| 標準（リード文＋コンテンツ＋出所） | `基本スライド` |
| 左右比較・Before/After | `基本スライド-２列` |
| 図を全面に置く | `基本スライド-線無し` |
| セクション見出しのみ | `基本スライド-タイトルのみ` |
| 白紙から組む | `白紙` |

`基本スライド2`（タイトル左に縦バー）、`基本スライド3`（上部に横帯）はデザイン違い。**1つのデッキ内では1系統に統一する。**混ぜない。`(青)` 付きは配色違いなので、これも混ぜない。

### 4. 作る

python-pptx で作る場合の実装は `references/build-with-pptx.md` を読む。テンプレを開いてレイアウトを指定し、プレースホルダに流し込む。**新規プレゼンテーションを作らない。必ずテンプレを起点にする。**

```python
from pptx import Presentation
prs = Presentation("${CLAUDE_PLUGIN_ROOT}/assets/hoda-template.pptx")
```

グラフは画像として貼る（作図は `hoda-peer-benchmark` のチャート作法に従う）。

### 5. 作法チェックをかける

書き出したら `references/style-rules.md` の全項目を自分でチェックする。特に文末の「。」、✓の使い分け、出所の位置、ですます調は機械的に確認できる。

## スライド作法（保田研の暗黙知）

**これは口頭でしか伝わっていなかったルール。破ると必ず指摘される。**

### 文章

- **ワンメッセージはスタンスを取る。** それを裏付けるファクトや論理はコンテンツ部分に置く。リード文で「〜という側面がある」「〜が課題と考えられる」と逃げない。「〜すべき」「〜である」と言い切る。
- **文末の「。」は使用しない。** 全スライドで統一する。**引用の中でのみ「。」を使ってよい。**
- **ですます調にしない。** 常体で書く。
- 体言止めと言い切りを混ぜても構わないが、1枚の中では揃える。

### 箇条書き

- **第1階層は「✓」。**
- **その下の階層に入れたいときは「・」。**
- 「●」「■」「-」「1.」は使わない。
- 3階層以上は作らない。作りたくなったらスライドを分ける。

### 図表

- **グラフや表の横線（横罫線・グリッド線）は基本入れない。**
- **財務系データのグラフの単位は基本「百万円」で統一。**
- **何の表・グラフか分かるようにする。** タイトルを必ず付ける。「売上高」ではなく「主要5社の売上高推移（FY2016-FY2025）」。
- 配色は `references/style-rules.md` のテーマカラーに従う。
- **対企業の提案の際は、随所でその企業のロゴカラーを仕込む。** 主役の系列・強調ボックス・章扉のアクセントに使う。

### 出所

- **必ず書く。**
- 表記は `出所：〜〜〜〜` の形式。「出典」ではなく「出所」。
- **スライドマスターの左下のテキストボックス**（`基本スライド` 系のレイアウトに用意されている、左0.49in／上7.00in のプレースホルダ）に書き込む。本文中に置かない。
- 2列レイアウトでは左右それぞれに出所欄がある。左右で出所が違うなら両方埋める。

```
出所：〇〇株式会社「有価証券報告書」（FY2025）よりチーム作成
出所：EDINET開示データを基にチーム作成
```

### 禁止事項

- **ハイパーリンクは使用しない。** URLを見せる必要があるならテキストとして書く。
- **極力Busyなスライドにしない。** 1枚に詰め込みすぎない。要素が多いと感じたら分割する。目安：本文の箇条書きは1枚6行まで、図は1枚2つまで。

### 印刷・転送を前提にする（対企業プレゼンで必須）

企業では**2ページを1枚にして白黒印刷**して読まれることがほとんど。また、当日参加できない人にファイルが転送される。

- **半分のサイズでも読める文字サイズにする**
- **グラフは白黒だと系列が判別できなくなる。グラフ内に直接ラベルを振る**
- 単独で読んでも分かるようにしたくなるが、そうするとワーディになる。**文字を大きくする・太字・丸で囲むで、シンプルなのにメリハリのあるスライドにする**
- **一番確実なのは、印刷して読み返すこと。**対企業プレゼン前は白黒・2in1で実際に刷る

詳細は `references/style-rules.md` の該当節。

### フォント

- 日本語は **ＭＳ Ｐゴシック**（テンプレのテーマで設定済み）。
- 欧文は Segoe UI（テーマ設定済み）。
- **テンプレのテーマフォントをそのまま使えば正しくなる。**個別のテキストボックスでフォントを上書きしない。
