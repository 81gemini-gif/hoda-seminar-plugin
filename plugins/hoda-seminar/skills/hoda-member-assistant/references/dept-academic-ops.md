# 授業運営部

## この部署は何をする部署か

**毎回のゼミの時間を設計して回す。**

重要な前提：**ここは先生がほとんど噛んでいない。** 基本的にゼミ長＋授業運営部で設計している。

- 輪読のコンテンツは何にするか
- 輪読ファシリは誰を立てて、いつまでに事前課題をアナウンスするか
- PJのワークにどれくらい時間を取るか
- いつをマイルストーンにして、いつに発表を予定するか
- ゲスト講師が来るときのアレンジ

下の階層を見るとやることは多岐に渡るが、**大枠は「輪読とPJの方針を前もって決めて、進捗管理すること」**に尽きる。

### マインド（一番大事なところ）

上に書いたのは**表立った仕事**。本質的に授業運営部は、**ゼミの時間が円滑に進行できるようにあるもの。**

なので、

- 皆のアテンションが薄いとき
- 移動が遅いとき
- 締めるところが締まっていないとき

**そこを締める役割**が本来ある。**これを部署の全員が持っていることが重要。**

## 1. 学期前：輪読コンテンツの選定

### 母体

**次期履修予定の生徒が休み期間中に提出した履修選抜課題（＝輪読ファシリ資料）。** ここから実際に扱う題材をピックアップする。

### 進め方

**授業運営部のメンバー3〜5名がそれぞれ ◎ / ○ / △ / × を書き込んでいく。** 記号だけでなく、**「こういう理由でやるべき／やるべきでない」を必ず書く。**

シートは**1行＝1人の提出者**で、**評価者ごとに「記号列＋コメント列」の2列が横に並ぶ**形。最後に**先生用の列**を置く。列構成とテンプレの生成手順は `references/sheet-templates.md` にある。

> 参考（内部リンク）：26春輪読マテリアル決定用シート
> https://docs.google.com/spreadsheets/d/1ZTwTkYwS2inP3dIlTHSj8ZRslJ7JqJyPsOpF0kmHnBU/edit?gid=0#gid=0

### 選定基準（3つの軸で見る）

#### 軸1：内容

- **絶対条件：コーポレートファイナンス的な観点でゼミにとって学びのある内容か。** このゼミはコーポレートファイナンスを扱うゼミなので、ここは外せない
- 次点：**ESG投資や人的資本経営**に関連するお題があるとまあまあ良い

**実際の落とし方**：面白い題材でも「ファイナンス要素が無さ過ぎる」「これは別のゼミがやるもので保田研がやるものじゃない」で見送りになる。**逆に、あと一歩ファイナンスに結びつければ「保田研だからやれる輪読」になるものは、そう書いて引き上げる。**

#### 軸2：先生がよく言っている3つの基準

**いずれかに該当していると、かなり良いと言える。**

1. **査読付きのしっかりとした実証論文で、お作法から何から何まで学べる、シンプルに良くできた論文**
2. **「学生らしい答えの無い青臭い議論」ができる、抽象的なトレードオフ系の議論が生まれるもの**
3. **世の中的に話題性のあるケースや書籍**

#### 軸3：ファシリ資料の質と、提出者がファシリを務まるか

**題材自体は一旦置いて、ここも必ず見る。**

- いくら良い題材でも、そこから立てた**ディスカッションポイント（DP）**がクソだったり、過程の分析が酷かったりしたら採用する意味はあまりない
- **最初に評価すべきこと**：
  - **その輪読をやることでゼミ生の議論が盛り上がるか**
  - **それが学びになっていくか**
  - **何を目的として、何を学ぶことができる輪読なのか**
- **製作者がファシリとしてやれるかも地味に大事。**「このメンバーがこのお題で、こいつと組ませてファシリをやったら面白い輪読になるか／ならないか」まで入れて評価する

### 実際に効いている判断軸（3軸の外側）

シートのコメントを見ると、上の3軸以外にこれらが繰り返し出てくる。**評価するときはここも見る。**

| 判断 | 中身 |
|---|---|
| **輪読向きか** | 面白くても「個人研究（GP）で聞きたい話」であって輪読向きでない題材がある。**全員で議論する形になるか**で切る |
| **難易度と足並み** | 「一定置き去りにされる人が出そう」なものは、**前提知識を先に扱う回を挟む**か、学期後半に回す |
| **新規生への効果** | 学期前半には**「輪読ってこんな感じだよ」と新規生に掴んでもらえるもの**を置く。イベントスタディなど基礎的な手法を学べるものは価値が高い |
| **被り** | 同じ事例・同じ論点の提出が複数ある。**被ったら片方を落とすのではなく、まとめるか、日英で分ける** |
| **組み合わせ・シリーズ化** | 「AとBを同時に扱ったら面白い」「両方を踏まえたキメラを作って1回で回す」。似た題材が集まったら**シリーズとして束ねる**（例：アクティビストシリーズ、理論のお勉強シリーズ、株主還元シリーズ、財務分析シリーズ） |
| **学期内の配置** | 「学期前半に」「学期後半に」まで書く。**採否だけでなく、いつやるかまでシート上で決める** |
| **日英の割り振り** | 「英語研で面白いかも」「日英両方でできそう」。**同じ事例を日英で扱う**判断もある |

### 学期全体の設計をシート上でやる

**候補を1本ずつ採否判定するだけでは、学期の設計にならない。**シートの最下部に、学期全体に関する議論を書く。

- **今学期の裏テーマを何にするか**（例：IR、株主還元、コングロマリット）
- **シリーズが増えすぎていないか**（「アクティビストシリーズはどれか一つにしませんか？」のような整理）
- **手法の習得をどこで入れるか**（実証分析の基本書、イベントスタディ、債券の基礎知識など）

## 2. 学期前：ファシリの決定と依頼

### ファシリの構成

- **日本語2名、英語2名の計4名。**
- **4名のうち1名は、その題材を選定して資料を作成した本人。**

### 組み合わせのバランス

- **新規生＋既存生**、または**ファシリ未経験＋経験者**のペアを意識する
- **ファシリの機会はなるべく平等に回ってくるようにする**

### タイムライン

| 時期 | やること |
|---|---|
| **学期開始1ヶ月前** | ファシリまで決める必要はない。選定作業を進める |
| **学期開始3週間前** | **授業運営部で選定したシートを先生に共有し、おおよその方針・意向を聞く** |
| その直後 | それを踏まえて**第1〜4週目くらいまでの題材とファシリを決定してしまう** |
| **輪読日の2週間前まで** | **ファシリに依頼を出す** |

**ファシリは早く決める分には問題ない。**ただしファシリ側からするとまあまあな負担なので、**遅くとも輪読する日の2週間前には依頼しておく。**

### 依頼の出し方

各週の**ファシリチャンネルを作成**し、**ファシリ候補者＋ゼミ長＋SA**を招待する。その上でファシリをメンションして依頼文を送る。

**依頼文に入れると親切なもの：**

- **何月何日の何限**にやるか
- **どの題材**でやるか
- **日英どちらのファシリで、誰が誰とペアか**
- **いつまでに何を終わらせておくべきか**
- **困ったら何を見て、誰に聞けばいいか**

## 3. 輪読当週までの進行（ファシリのいろは）

授業運営部が管理する部分でもあり、ファシリ本人に伝えるべき部分でもある。

| 時期 | やること |
|---|---|
| **1週間前（金〜日）** | DPと全体の進行の荒い設計、事前課題の検討。それを**先生・ゼミ長・SA・授業運営部などに投げてFBをもらい、最終確定させる** |
| **月曜、遅くとも火曜午前中** | **次週の輪読の事前課題を投げる** |
| **火曜〜輪読前日の日曜** | 当日のファシリ資料を完成させる（これ以前から作り始めても構わない） |
| **土日** | **事前課題の提出が集まってくるので、内容を適宜見る。**当日の資料やファシリの進行にどう盛り込むかを考えておく |

## 4. 学期前：PJの設計

### 先生とのMTG

**学期開始1ヶ月前を目安に、先生とゼミ長で「今期のPJについて」というMTGをセットする。**

### 配属を決める

それを踏まえて**ゼミ長＋授業運営部**で、誰をどのPJに配属するかを決める。

**希望を取るかどうか：**

- 取っても良いが、**全員の希望を聞くとすごいコストになる**
- 取るなら**絶対に制約を設ける**
- **「全員の要望を通すわけではない」と先に断りを入れる**

**配慮すべきバランス（全体最適を目指す）：**

- 男女のバランス
- 学年のバランス
- 能力的なバランス
- その人同士の相性
- **以前一緒にPJをやったか否か**

**難航したら：**

時間が無かったり決めるのに難航している場合、**ゼミ長が舵を取ってスパッと意思決定して良い。**最終的にゼミ長にあるのは人事権くらいなので。

**進め方のコツ：**

**ゼミ長の中であらかじめ「大枠このチーム構成で行きます」というのを組んでおいて、それを基に授業運営部も入れてMTGをし、その場で決め切ってしまう**のが良い。

### チームリーダー

**チームを決めるときに、その場でリーダーも決めてしまう。**後回しにしない。

### チャンネルの作成

- 各チームのチャンネルを作成して招待する
- **チームメンバーだけでなく、ゼミ長とSAも各チャンネルに入れる**
- **企業とNDAを締結するようなチームは Private で作る**

### アナウンス

**学期開始時くらいまでに、以下を明らかにしてアナウンスする。**

- どのPJがいつ中間発表か、いつ最終発表か
- どんなテーマで、最終的なアウトプットはどんなものか

**そしてそれを基に、いつのゼミの時間を発表に充て、いつをPJワークにするかを決める。**

## 5. 毎週の運営

### コマの原則

**4限＝輪読、5限＝PJワークが原則。**

ただし発表があったりゲストが来たりと、いろんな都合で変わる。**PJのワークを柔軟にずらしたり消したりしつつ調整する。**

### 毎回やること

- [ ] **授業開始前に、ホワイトボードにその日のタイムスケジュールを書いておく**
- [ ] **前日までに、Slackで同じ内容をアナウンスしておく**

### 発表がある回

- [ ] **FBシートを作成する**
- [ ] **授業開始前までにアナウンスして配る**

**シートの列構成と、テンプレを生成する手順は `references/sheet-templates.md` にある。**

FBシートの要点：1行＝1人の記入者、1チームにつき2列（`良かったところ` / `質問 or 改善が必要な点`）。チーム見出しは `TeamN(リーダーのニックネーム)`。**自分のチームの列には「自分の班」と書いて飛ばす。**

## 6. ゲストスピーカーの受け入れ

稀にゲストスピーカーが来る。**授業運営部から2〜3名の担当者を立てて、ロジ面をきちっとやる。**

### 事前

- [ ] **ゲストスピーカーとのメールでのやり取り**
- [ ] **会場を押さえる**
- [ ] **水を人数分用意しておく**

### 当日

- [ ] **お出迎え**
- [ ] **時間を見て、最後の質問にして切る。**皆さん忙しく、予定にケツがあるので、ここは必ずやる
- [ ] **センキュースピーチをする**

### 事後

- [ ] **後日、お礼メールを送る**
