# ゼミ生お助けエージェント

保田研の部署実務と、ゼミ生全体に効くコツをまとめる。**手順書ではなく、やってみて分かったこと**を集めてある。

## 使い方

1. **相談者がどの部署か、何に詰まっているかを最初に確認する。**部署が分かれば該当の参照ファイルだけを読む。全部読まない。
2. 手順そのものが必要なら、対応する既存スキルに橋を渡す。
3. ゼミ長からの相談なら `hoda-zemicho-assistant` を併用する。あちらは「4部署をどう見るか」を持っている。

## 部署別の参照ファイル

| 部署 | ファイル | 主な所管 |
|---|---|---|
| **授業運営部** | `references/dept-academic-ops.md` | 学期内スケジュール決め、輪読コンテンツ決め・担当者依頼、PJ決め・進行 |
| イベント運営部 | （未収録） | イベントの管理・運営、共通アウトフィット作成 |
| 広報部 | （未収録） | インスタ管理・運営、聴講希望フォーム管理、HP管理・運営 |
| 会計 | （未収録） | ゼミ費の徴収・管理、イベント予算・精算 |

## シートのテンプレを作る

授業運営部が作る2つのシートは、構造を `references/sheet-templates.md` に持っている。「FBシート作って」「輪読の選定シート作って」と言われたらこれを読む。

| シート | いつ作るか |
|---|---|
| **発表FBシート** | 発表がある回。授業開始前までに作ってアナウンスする |
| **輪読マテリアル選定シート** | 学期前。履修選抜課題から題材を選ぶとき |

## 手順が必要なときの行き先

| 相談 | スキル |
|---|---|
| 週次シートの列構成、輪読ファシリの型、アナウンスの書き方 | `hoda-weekly-ops` |
| 学期スケジュールの逆算設計 | `hoda-semester-plan` |
| 合ゼミ・合宿・工場見学・講演会の幹事 | `hoda-event-kanji` |
| ゼミ長としての立ち回り | `hoda-zemicho-assistant` |
| PJリーダーとしての立ち回り | `hoda-project-leader` |
| ゼミの前提知識・行動規範 | `hoda-context` |

## 全体に効く原則

部署に関わらず、保田研の運営で共通して効くもの。詳細は `hoda-context` スキルの references/code-of-conduct.md にある。

- **ATI（圧倒的当事者意識）とラストマンシップ。**部署の仕事は「誰かがやってくれるもの」ではない
- **リマインドされたらおしまい。**催促される状態になった時点で遅れている
- **Slackは24時間以内に何らかのリアクション。**スタンプ1つでいい
- **依頼は早いほど良い。**受け手には準備の時間が要る
- **決まっていないことを、決まっていないと明示して共有する。**沈黙が一番よくない
