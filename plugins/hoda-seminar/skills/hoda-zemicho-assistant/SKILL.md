# ゼミ長アシスタント

## ゼミ長の立ち位置

**ゼミ長は部署の実務をやる人ではない。**部署（授業運営部・イベント運営部・広報部・会計）が実務を回し、ゼミ長は全体を見て、詰まったところを巻き取るか他に移管する。

- **毎学期交代**が原則。**3名体制**が定着している
- **役割分担は明文化されていない。**実態としては、一方が授業運営とゼミ全体の大きな意思決定を拾い、もう一方がイベント・対外活動・会計・広報のとりまとめを請け負う形が取られてきた
- 40名規模。**人は毎学期入れ替わる**（留学、休学、出戻り）

---

## 学期の頭にやること（最優先）

### 1. 3名の役割分担を決めて書き残す

**明文化されていないのが現状の仕様。**引き継ぎのたびに再発明されるコストがあるので、**学期の頭に3名で分担を口頭合意し、Slackに書いてピン留めする。**

分担のたたき台：

| 担当 | 見るもの |
|---|---|
| **A：授業・全体** | 授業運営部、輪読・PJの進行、先生との窓口、ゼミ全体の意思決定 |
| **B：対外・イベント** | イベント運営部、合同ゼミ、企業訪問、他大学との調整 |
| **C：広報・会計・内務** | 広報部、会計、聴講管理、名簿管理、新規メンバーのオンボード |

**「誰も見ていない領域」を作らないことが目的。**きれいに3等分することではない。

### 2. 学期スケジュールを確定させる

→ `hoda-semester-plan` を回す。学期開始時点で向こう1〜2ヶ月分の輪読スケジュールが決まっている状態を作る。

### 3. 部署の配属を決める

- 初回のゼミで部の配属調整を行う（過去の運用では第1回に20〜30分取っている）
- **在籍1学期目のメンバーを各部に散らす**
- 部ごとにSlackチャンネルがあるか確認する

### 4. 新規メンバーのオンボード

- [ ] Slackに全員が入っているか確認する（名簿の `slack` 列）
- [ ] Driveの共有フォルダにアクセスできるか確認する
- [ ] **保田研の型を説明する。**輪読の事前課題、スライド作法、キメヘン、360°FB。**「前からいる人は知っている」を前提にしない**
- [ ] 名簿に追加する（`year` に在籍学期数を入れる）

## 週次で見ること

毎週、この5点だけ確認する。全部自分でやろうとしない。

| # | 確認 | 詰まっていたら |
|---|---|---|
| 1 | **今週のシートが埋まっているか**（4限・5限の内容、ファシリ依頼が「済」か、聴講可否） | 授業運営部に確認。埋まらないなら巻き取る |
| 2 | **来月のイベントの幹事が動いているか** | 幹事チャンネルを見る。止まっていたら声をかける |
| 3 | **各PJの進捗** | リーダーに聞く。詰まっていたら先生に上げる判断をする |
| 4 | **今週流すアナウンス**（締切、日程変更、提出物） | 下記参照 |
| 5 | **反応がないメンバーがいないか** | 個別に声をかける。留学準備・就活・体調で沈むことがある |

---

## アナウンスの型

- **`J or E` 列を見て、英語話者が読める形になっているか必ず確認する。**日本語だけで流すのは在籍者の約4割を置き去りにする
- 締切は**日付と時刻**を書く（「金曜まで」ではなく「11/21（金）23:59まで」）
- 提出先（フォーム／Drive／Slackスレッド）を明記する
- **アクションが必要な人を名指しする**（「発表班のみなさん」ではなく具体的に）

Slackコネクタが使える場合は `slack_send_message_draft` で下書きを作る。**いきなり本送信しない。**

## 合同ゼミの監視（ゼミ長固有の仕事）

**幹事に任せきりにしない。**過去の運用でも明確に言語化されている。

> ゼミ長はこれを監視しておいて、必要あれば巻き取ったり他に移管したりすること

- [ ] 夏（7〜8月）に大阪大合ゼミの幹事を立て、**Slackに幹事チャンネルを作る**
- [ ] 9月に早稲田大合ゼミの幹事を立てる
- [ ] **先方大学とのやり取りがこまめに回っているか、週次で幹事チャンネルを見る**
- [ ] **10月末までに「どの班が発表するか」を全体の議論に上げる。**発表班の決定は毎回ギリギリまで決まらないので、ゼミ長が能動的に議題化する
- [ ] 資料提出の締切と形式（pptxかpdfか、誰が束ねるか）を確定させる

---

## 判断が要るとき

| 状況 | 判断軸 |
|---|---|
| 幹事が動いていない | まず声をかける → 2週間動かないなら巻き取るか移管する。**開催1ヶ月前を切ったら即巻き取る** |
| PJが詰まっている | リーダーと話す。データが取れない・手法が分からない系は**先生に上げる。2週間粘らせない** |
| メンバーが来なくなった | 個別に連絡する。事情（就活、体育会、他ゼミ、体調、留学準備）は保田研では普通。**責めずに、その学期の関わり方を再設計する** |
| 日程がぶつかった | 外部固定（合ゼミ、先方企業、コンペ締切）を優先。動かせるのは学内の回だけ |
| 先生に上げるべきか迷う | **上げる。**"Action trumps everything." 抱え込んで遅れる方がコストが高い |

## 引き継ぎ（学期末）

**ここが保田研で最も価値のある仕事。**学期単位で人が入れ替わる制度なので、引き継ぎがないと毎学期ゼロから始まる。

引き継ぎ資料に必ず書くもの：

- [ ] 3名の役割分担を、**実際どう分かれていたか**（決めた通りではなく、実態）
- [ ] 今学期のシート（`その他` 列の判断メモを残したまま）
- [ ] **うまくいかなかったこと**と、その原因の見立て
- [ ] 外部との連絡先（他大学のゼミ長、提案先企業の窓口、コンペ事務局）
- [ ] Drive・Slackのどこに何があるか
- [ ] 各イベントの幹事を**いつ立てたか、それが早かったか遅かったか**
- [ ] 継続フォームで集まった次学期の輪読候補

**引き継ぎ資料はDriveに置き、Slackでピン留めする。**個人アカウント依存の場所に置かない。
