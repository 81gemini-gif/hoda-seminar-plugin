# PJの学期タイムライン

リーダーが押さえる週次のマイルストーン。3本柱（①仲良くなる ②方向性を共有する ③進捗を実感してもらう）のどれに効く作業かを併記する。

## 第1〜2週：立ち上げ

- [ ] **①【最優先】チームメンバーでご飯／飲みをセッティングする。**この週にやる
- [ ] ①顔合わせで、在籍学期数・使えるツール・週に出せる時間・動けない期間を全員に言わせる
- [ ] ②提案先企業／研究テーマの理解を全員で揃える。`hoda-company-scan` を1回回して、全員が同じ事実を持っている状態を作る
- [ ] ②**キメヘンの第1稿を埋める**（→ `hoda-kimehen`）。粗くてよい。**空欄のまま進まない**
- [ ] ②「誰に何を伝えるPJか」「自分たちがやる意義」「このチームのユニークネス」を言語化してチャンネルにピン留めする
- [ ] ③Slackのチームチャンネルを作る。ドキュメントの置き場（Drive）を決めて共有する
- [ ] ③中間発表・最終発表の日から逆算した週次スケジュールを作り、チャンネルにピン留めする

## 第3〜5週：仮説を立てる

- [ ] 財務分析を回す（`hoda-value-driver-tree` → `hoda-peer-benchmark`）
- [ ] ②**「この会社の何が問題か」の仮説を3つに絞る**
- [ ] ③仮説ごとに、検証に必要なデータと担当を割り当てる
- [ ] ②キメヘンを更新し、更新したことを明示的に流す
- [ ] ③この時期にSlackが止まりやすい。**沈黙48時間でメンション**

## 中間発表 D-14

- [ ] ②**ストーリーラインを1行×N枚で書き出し、チームで読み合わせる**
- [ ] 抜けている裏付けを洗い出し、残り2週間で取れるか判断する。取れないなら主張を弱めるか、別の裏付けに切り替える
- [ ] ③**この時点でスライド初稿に着手していないなら、主張を減らす判断をする**

## 中間発表 D-7

- [ ] スライド初稿を完成させる（`hoda-slide-deck`）
- [ ] **チーム内でリハーサルを1回やる**
- [ ] 役割分担（誰がどのスライドを話すか、質疑の担当）を決める

## 中間発表 当日

- [ ] `hoda-presentation-readiness` の当日の節を回す
- [ ] **FBをメモする担当を決める（できれば紙とペン）**
- [ ] ③**もらったFBをその日のうちにテキスト化してチャンネルに残す。**記憶に頼らない

## 中間発表の翌週

- [ ] **360°FBをチーム内で実施する**（→ `hoda-360-feedback`）
- [ ] ③FBのどれに対応してどれを対応しないかを決めて共有する
- [ ] ②360°FBで出た「方向性が見えない」系の指摘は、②の言語化不足のサイン。キメヘンを作り直す

## 中間〜最終

- [ ] 分析を深める。バリュエーション・定量インパクトの試算を入れる（`hoda-valuation`、`hoda-cross-swot`）
- [ ] **社会的価値の軸が入っているかを確認する。**財務的に正しいだけの提案は保田研では評価されない
- [ ] ③**進捗を実感させる。**「先週からここまで進んだ」を週次で明示する
- [ ] ③4年生は就活・卒プロで動けなくなる時期がある。役割を組み替える

## 最終発表 D-14 / D-7 / 当日

→ `hoda-presentation-readiness` を回す。

## 最終発表の翌週

- [ ] **360°FBを実施する**
- [ ] 資料をDriveの所定の場所に置く（ファイル名に日付と発表名）
- [ ] （企業PJなら）**感謝のメールを送る**
- [ ] ①打ち上げをやる。360°FBでも「プロジェクト終わったら打ち上げで飲み会やってほしい」は実際に出ている要望
