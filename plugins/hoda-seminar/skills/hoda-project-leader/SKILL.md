# PJリーダーの手引き

## リーダーの仕事は究極3つしかない

| # | やること | 一言で |
|---|---|---|
| **①** | **チームメンバーと仲良くなる** | まずご飯に行く |
| **②** | **進むべき方向性を共有する** | キメヘンで言語化する |
| **③** | **共に進捗を実感してもらう** | **リーダーの仕事の8割はここ** |

**リーダーは一番分析ができる人ではない。**チームが止まらないようにする人。分析を全部自分でやり始めた時点で、リーダーの仕事をしていない。

---

## ① チームメンバーと仲良くなる

**PJが始まったらすぐ、チームメンバーでご飯なり飲みなり何でもいいからセッティングする。**

- **これを最優先でやる。**分析の話より先
- 「落ち着いてから」は来ない。**PJ開始の週にやる**
- 形式は問わない。ご飯、飲み、カフェ、なんでもいい

### なぜ効くか

後半で必ず「言いにくいこと」を言う場面が来る。稼働が落ちた、締切に間に合わない、方向性が違うと思う——**これを言い合える関係を、余裕のあるうちに作っておく。**

360°FBでも繰り返し出てくる指摘：

> 一番年下で発言しにくかったり、自分が間違っているかもしれないから発言をためらってしまったりすることもあると思うけど、そこは遠慮せずにどんどん言ってほしい

> 雰囲気的に発言しづらいかもしれないけど、一回発言すれば後は楽になる

**発言しやすい場は自然にはできない。**リーダーが作る。

### 顔合わせで聞いておくこと

- 在籍学期数（保田研の型をどこまで知っているか）
- 使えるツール（R / Python / Excel / パワポ）と、財務分析の経験
- **週に出せる時間と、動けない期間**（就活、体育会、他ゼミ、インターン、留学準備）
- その人が今回のPJで伸ばしたいこと

ここを飛ばすと、後の割り振りを必ず間違える。

---

## ② 進むべき方向性を共有する

**キメヘンを作る**（→ `hoda-kimehen`）。その上で、次の3つをはっきり言語化してメンバーに渡す。

| 問い | 何を言語化するか |
|---|---|
| **誰に何を伝えるPJなのか** | 聞き手とメインメッセージ。キメヘンの表そのもの |
| **自分たちがこれをやる意義は何なのか** | なぜこのチームがこのテーマをやるのか |
| **このチームのユニークネスは何なのか** | 他の班にはなくて、うちにはあるもの |

**ここが曖昧なまま走ると、議論が発散する。**360°FBで実際に出た指摘：

> 完成像が見えないから、それぞれが好きにやりはじめてて、みんな違う角度で意見を出してくるから、それぞれの意見について調べなきゃいけなくて、みんなが一つのことに対して向かえていない

> 仮でもよいので**自分のスタンスをいち早く決めること**。決めるのが仕事

**完璧に固まってから共有しようとしない。**仮でいいので早く出して、走りながら直す。"Action trumps everything."

### 言語化したら、書いて置く

- Slackのチームチャンネルに**ピン留めする**
- 迷ったら全員がここに戻れる状態にする
- 更新したら「更新した」と明示的に流す

## ③ 共に進捗を実感してもらう

**リーダーの仕事の8割がここ。**ここができれば言うことはない。

### Slackを動かし続ける

**Slackはみんなほっとくと全然動かさなくなる。**これは前提として織り込む。

| やること | 目安 |
|---|---|
| **スレッドに対してメンバーをメンションしまくって返信させる** | 常時 |
| **動きが消えて1〜2日でメンションできると素晴らしい** | 沈黙48時間が上限 |
| **メンションしてもダメそうならDMにも行って猛プッシュする** | 段階を上げる |
| **1つのスレッドが返信30〜60件あると良い状態** | 議論が回っている目安 |

**この管理と尻叩きができれば言うことない。**

補足：

- 全員に一斉メンション（@channel）ではなく、**名指しで聞く**。「誰か答えて」は誰も答えない
- 聞き方を具体的にする。「進捗どうですか？」ではなく「〇〇さん、Aの分析、今どこまで行ってますか？詰まってたら言ってください」
- DMに行くときは責めない。**動けない事情があることの方が多い**（就活、体調、他の締切）。タスクを減らす・役割を変える判断も含めて話す
- 逆に、**メンバーが何かを出したら必ず反応する。**リーダーが無反応だと、次から出てこなくなる

### 情報をDMに閉じない

360°FBで繰り返し出ている指摘：

> Slackで連絡を取る際に個別のDMを使うことが多かったと思うんだけど、チーム間で誰がどれくらい稼働できてるかとか、誰が今何をやってくれてるのかが分かりにくかった

> 情報共有の点で、個人的な話なら個人的に言うのもあっていいけど、できれば**全体の見えるところで個人個人と話したりタスクを渡してほしい**

**尻叩きはDMでいい。タスクの割り振りと進捗はチャンネルでやる。**

### 毎週の定例MTGに目的をもって臨む

**MTGが気づいたら1時間、2時間、3時間…みたいなことは絶対に避ける。みんな時間は有限。**

#### MTG開始前の20分

**リーダーは、MTG開始の20分前を使って先に考えておく。**ここをやるかどうかで会議の長さが倍違う。

考えておくこと：

1. **今日のアジェンダ**（何を話すか）
2. **プロジェクトのゴールに対する今の現在位置**（どこまで来たか）
3. **今後の進め方の全体観**（この先どう進むか）

#### MTGの進め方

1. **冒頭で上の3つを共有する。**いきなり議題に入らない
2. **最低限の共有と議論を最短距離で行う**
3. **喋っていない人に話を振る。**これはリーダーがやらないと誰もやらない
4. 決まったことと、次までのタスク・担当・期限を確認して終わる

#### 議事録は自動化する

**みんなでお金を出し合って Notion AI などで自動化する。**

理由：**全員がMTGに200%集中している時間を作りたいから。**誰かが議事録を取っている状態は、その人が議論に参加できていない状態。

- 自動議事録が使えないなら、**議事録担当を毎回ローテーションする**。同じ人に固定しない
- MTG後、決定事項とタスクだけは人の手で整理してチャンネルに流す（AIの議事録は長すぎて誰も読まない）

### 進捗を「実感」させる

**進捗管理と進捗の実感は別物。**タスクが消化されているだけではメンバーは前に進んでいる気がしない。

- 週次で「**先週からここまで進んだ**」を明示的に言う
- 誰の貢献で進んだかを名指しで言う
- 中間地点で、キメヘンの表を更新して見せる。**最初の仮説からどう変わったか**が見えると進捗を実感できる
- 詰まっている週も「今週は詰まった。原因は〇〇。来週これをやる」と言語化する。**沈黙が一番よくない**

## 詰まったときの判断

| 症状 | 対処 |
|---|---|
| **Slackが2日以上止まっている** | ①のメンション、②のDMの順で動かす。**3日放置しない** |
| **議論が発散する** | ②に戻る。キメヘンで「このスライドはどのヘンに効くか」で切る |
| **MTGが長い** | 開始前20分の準備をしていない。次回から必ずやる |
| **特定の人しか喋らない** | リーダーが名指しで振る。順番に一周させてもいい |
| **メンバーが動かない** | まず1on1。時間が取れない事情は保田研では普通。**タスクを減らして役割を変える**方が、詰めるより機能する |
| **データが取れない** | 3日以上詰まったらゼミ長・先生に上げる。`hoda-dataset-howto` `hoda-research` を確認 |
| **実証分析の手法が分からない** | `hoda-empirical-roadmap` を見る。それでも詰まるなら先生に聞く。**2週間自力で粘るのは時間の無駄** |
| **締切に間に合わない** | **前日ではなく1週間前に言う。**粗い状態で早く共有する方が評価される |
| **自分が抱え込んでいる** | 360°FBで最も多くリーダーが指摘される点。**「どれをやりたい？」ではなく「あなたは〇〇だからこのタスクをお願い」**と割り振る |

## 英語チーム／日本語チームをまたぐとき

- 同じ企業に日英2チームが付いている場合、**学期頭に切り口を分ける合意をする**
- 中間発表以降、両チームで一度突き合わせる。同じ会社に矛盾する提案を出すと発表の場で必ず突かれる
- チーム内に英語話者がいるなら、**Slackの重要な連絡は英語も添える**
